# Reproducible Math Art as a Data Pipeline

Every image in this repo is generated by a mathematical formula, not a model,
not a photograph, not a scene graph. That choice gives us byte-level
determinism: same spec ⇒ byte-identical PNG across machines and time.

## What determinism buys

1. **Idempotency without recompute.** The formula hash *is* the skip decision.
2. **Cheap auditability.** Every pixel has a mathematical lineage.
3. **Columnar analytics.** dbt runs over metadata only, never images.

## What determinism costs

`polar_loom` at 1600×1200 with `rings = 32`:

    1600 × 1200 × 32 × 3 ≈ 184 million sin/cos evaluations

Complexity is `O(pixels × rings)`. 8K with 128 rings pushes into
minutes-per-image on a single core. Neural rendering wins scale; it loses
reproducibility.

## Metrics that matter

    us_per_megapixel    = runtime_ms / (w × h) × 1e6
    bytes_per_megapixel = bytes_full / (w × h) × 1e6

The first compares intrinsic formula cost; the second drives storage tiering.

## When not to use this approach

- Photorealism required → neural rendering
- Interactive latency required → not this
- Semantic control required → not this

## When to use it

- Reproducibility is a hard requirement
- Parameter sweeps matter
- Artifacts must be diffable and versioned

The formula is the fun part. The pipeline is the point.
